# 재무설계 흐름과 공통원장

[IFPK 설명 글](https://m.blog.naver.com/ifpkkorea/224408454272)과 [공식 참가작 양식](https://www.ifpk.org/download?attach_file_usn=11074&data_usn=181809)을 확인했다. 아래 단계명은 제출양식에 맞춘다. 미국 [CFP Board 직업기준](https://www.cfp.net/ethics/code-of-ethics-and-standards-of-conduct)의 7단계는 품질 참고이며 IFPK와 같은 체계라고 단정하지 않는다.

## 여섯 단계와 증거

| 단계 | 이번 프로젝트에서 남길 결과 |
|---|---|
| 1. 고객과의 관계 정립 | 가상 상담 범위, 역할, 주택 유지 등 제약, 지원하지 않는 영역 |
| 2. 재무목표 설정 및 고객에 관한 자료수집 | 관측 통계·합성 입력·미확인 항목을 구분한 입력 버전 |
| 3. 고객의 재무상태 분석 및 평가 | 기준 현금흐름, 자산의 유동성, 대출 일정, 목표부족과 독립 검산 |
| 4. 재무설계안 수립 및 제시 | 같은 시작 상태·기간·충격에서 현행 유지와 대안 비교; 선택·기각 이유 |
| 5. 재무설계안 실행 | 실제 금융거래 대신 담당·기한·선행조건이 있는 모의 실행 계획 |
| 6. 재무설계안 점검 | 변경 신호·점검 주기와 재계산; 실제 사후관리 성과로 표현하지 않음 |

단계 4~6의 표는 해야 할 작업이다. 입력을 마련하거나 계산 코드를 실행한 사실만으로 고객의 동의·거래·장기 목표달성을 완료했다고 쓰지 않는다.

## 같은 돈은 한 번만 센다

원장의 기본 항등식은 `순자산 = 자산 - 부채`다. 현금에서 투자계좌로 옮기는 거래나 대출원금 상환은 그 자체로 순자산을 줄이지 않는다. 수익·소득·비용·이자·수수료와 목표를 위한 소비는 별도로 대사한다.

- 교육용 예금 배정은 기존 예금에 붙인 목적 표시다. 별도 자산을 더하지 않는다.
- 연체 원금은 기존 대출잔액의 부분집합이며 새 부채로 다시 더하지 않는다.
- 이미 발생한 미지급 의무와 아직 구매하지 못한 필수생활 필요를 구분한다. 후자는 자동으로 법적 부채가 되지 않는다.
- 현금 하한을 입력해도 부족한 현금이 생기지 않는다. 기존 하한 미달을 별도 표시한다.
- 주택과 인적자본의 가치를 즉시 투자 가능한 현금으로 더하지 않는다.
- 월별 계획과 실제 지급일은 다르다. 연간 비정기지출의 월평균만으로 지급일 유동성을 입증하지 않는다.

금액에는 통화, 명목/실질 기준, 세전/세후, 기준일, 표시단위를 둔다. 미래 명목 목표에 물가를 중복 가산하지 않는다. 연 실효수익률의 월 환산과 명목 대출금리의 약정 환산도 구분한다.

## 목표·선호·동순위

목표는 희망금액·최소수준·기한·우선순위·금액 또는 기한의 조정범위를 기록한다. 손실을 받아들이려는 태도와 필수지출·의무상환을 유지할 객관적 감당능력은 별개다.

가상 고객 v1의 교육과 은퇴는 동순위다. 임의로 목록 앞의 목표를 우선하지 않는다. 같은 순위에서 잉여를 나누는 비율, 최소수준 선충족 등 정책을 사용자가 정하거나 각각의 대안으로 명시해야 한다. 연구용 [원장 코드](../research/validation/integration/planning_core.py)는 동순위를 자동 해결하지 않고 거부한다. 이를 입력 순서로 해결된 기능이라고 설명하면 안 된다. 웹에서 동순위를 다룬다면 새 정책과 별도 시험을 확인한다.

현재 웹 예제는 의무지출·현금 하한 뒤 기존 교육·연금·투자 납입을 같은 비율로 충족한 후 추가예산을 배분하는 명시적 정책을 사용한다. 이는 연구용 원장에 없던 웹 정책이며 모든 동순위 목표의 최적 배분을 증명하지 않는다. [웹 입력의 추가 가정](../fixtures/provenance.json)을 확인한다.

## 대안 평가

먼저 지급의무 누락·연체·중복배정·출금 불가 자산 사용 등 실행불가를 확인한다. 이후 필수생활 미충족, 최저 현금과 부족기간, 목표별 부족액·시점·지속기간, 비용·조정 폭·실행 부담을 같은 순서로 비교한다. 확인하지 않은 선호 가중치로 종합점수를 만들지 않는다.

모든 목표는 공동 시나리오 안에서 함께 평가한다. 목표별 달성률을 독립이라고 가정하여 곱하지 않는다. 확률을 추정하지 않은 소득중단 스트레스는 성공확률이 아니다. 같은 충격 경로를 대안에 재사용하고 학습 표본의 최적화와 평가를 구분한다.

현재 원장 검증은 단일 통화·단순 월 사건의 좁은 구현이다. 실제 계좌·세금·연금·금리 재산정·지급일·누적 목표 실행을 모두 처리하는 엔진의 완료 증거가 아니다. [검증 범위](04-validation-history.md)와 [웹 상태](06-web-architecture.md)를 함께 읽는다.
